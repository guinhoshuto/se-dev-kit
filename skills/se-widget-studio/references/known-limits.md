# Known limits

What the Studio does not do yet, or does differently from StreamElements, and what to do instead. Each item names the evidence. Read this before planning marketing media; remove an item when its fix ships.

## Capture

- **`color-scheme: dark` on a transparent widget** shows on an opaque `#121212` box in screenshots, videos, and the tutorial replica (see the end of [catalog-authoring.md](catalog-authoring.md)). Do not work around it in the catalog; tell the user.
- **Runtime network.** Only Google Fonts load at runtime. A script the widget injects from a CDN (three.js, for example) does not load, so whatever depends on it breaks; stop before rendering marketing media and ask (see "Known gaps" in [studio-workflow.md](studio-workflow.md#known-gaps)).
- **Module scripts.** Import refuses a widget whose HTML loads a `<script type="module">` or an import map (`Only classic JavaScript script tags are supported; modules and import maps are not imported.`, `lib/importer.ts`), and the project stays `blocked`; the local CLI does not run it either. A library that ships only as an ES module (Jelly UI, in se-jelly-chat, 2026-10-16) cannot be tested in the Studio: do not edit the widget or shim the library, stop and ask the user how to check it.
- **Unproven font path.** A widget that reassigns the same stylesheet `href` has not been verified: look at the render before using it. Canvas text (`fillText`) with a Google Font is proven (see "Fonts" in [studio-workflow.md](studio-workflow.md#fonts)).
- **Clock in UTC.** Jobs format dates and times in UTC, where StreamElements uses the viewer's time zone: a fixture message `time` written as 09:34 at -04:00 showed "1:34 PM" (se-imessage-chat, 2026-10-15). Write fixture times in UTC for the clock you want on screen. A message with no `time` takes the Studio's own clock, which showed "12:00 PM" after a tutorial `setField` reloaded the widget.
- **A field with no `value`.** The Studio gives it `""`, in `fieldData` and in its placeholders. StreamElements' editor gives it `undefined` once it shows the widget's fields, so `{field}` and `{{field}}` read `undefined` in its canvas, and `onWidgetLoad` gets no such key (its overlay code, read on 2026-10-28). Code that needs a value there breaks only in the Studio: se-custom-chat's `const aniLetter = {animatedLetters} ? true : false;` becomes `const aniLetter =  ? true : false;`, a syntax error. Set the field in the theme the render uses (se-custom-chat's `data.json` sets every one); do not edit the widget.
- **jQuery effects stand still in the editor.** jQuery's `animate`, `fadeIn`, `slideDown`, and the other effects time themselves with `Date.now()`, which the interactive Studio and Gallery frames fix (`docs/RUNTIME.md`): there a `fadeIn(200)` stayed at opacity 0 after 1 s, and it finished with a live `Date` (jQuery 3.3.1, 2026-10-28). Screenshots, videos, and renders advance the clock, so the effects play in them; judge an effect in a render, not in the editor.

## Video

- **Store length.** An Etsy listing video lasts 5 to 15 seconds, at most 100 MB, between 2:1 and 1:2 (square included), and Etsy removes its audio (`presets/marketplaces/etsy-listing-2026-09.json`). The local Studio itself has no length cap: keep listing recipes within the preset, and set `marketplacePreset` so `validate` checks them.
- **Loops are never byte-identical.** Compositing leaves 1 to 4 levels of rounding between the first frame and its return; cut a loop at the first frame within 6/255 of frame 0 on all but 0.01% of the pixels (see [marketing-assets.md](marketing-assets.md#loops); `scripts/cut-loop.mjs` cuts a Studio job's MP4 within a mean of 1/255, or at a known period with `--period`, on a known beat with `--beat`).
- **Color.** Studio videos are converted with the BT.709 matrix and tagged BT.709 since 2026-09-29 (`a9904c8`); earlier ones are BT.601 without tags. A tool that re-encodes them lets FFmpeg read the tags instead of forcing `in_color_matrix`.
- **Frames are deleted.** Studio jobs never publish PNG frames, whatever `keepFrames` says. A poster or a mid-animation still of a stage video comes from `outputs.video.stills` (see [marketing-assets.md](marketing-assets.md#stills)), which jobs publish, and `scripts/cut-loop.mjs` cuts a loop from the MP4 itself.

## Machine

- **One render at a time.** Studio jobs and CLI renders wait for the machine-wide render slot (`~/.cache/render-slot`), and then for the machine check (the game, memory, a Remotion render from another tool): a CLI render before each recipe, a Studio job before it starts, 30 minutes at most for the slot and the check together. A client in a checkout without `dist/`, such as a new worktree, asks the machine check through the live checkout's build, the real path of `~/.claude/skills/se-widget-studio`; with no build anywhere it prints `machine check skipped: no engine build at <path>` and submits at once, and its job can give up with `RENDER_SLOT_TIMEOUT` after 30 minutes behind a long hold, as one did on 2026-10-25 behind a six-hour hold.
- **A chain that yields lets a Studio client in.** A chain that holds the slot in pieces with `hold --ceder` (the vault's `mutar_copia` rounds) yields only to whoever has a place in the render-slot queue. While the machine check names only the slot, its queue and memory, the client of a local Studio takes that place before it submits: `render-slot.ts status` lists it as `vez: se-widget-studio.job`, it prints `Waiting for the machine before submitting, in the render slot queue as "vez: se-widget-studio.job": <reasons>`, and at its turn it submits, with the slot left free for the job for 30 s. Until 2026-10-28 it only polled the check, which never saw such a chain's slot free: a capture waited 1 h 12 min and failed (#15). A client that runs an engine build older than that still polls.
- **Disk.** A 1080p PNG frame weighs 2 to 3 MB before encoding: 15 videos of 14 seconds peaked near 10 GB on 2026-09-26. Check the dry run's `plan.disk.summary` (CLI) or the estimate in [studio-workflow.md](studio-workflow.md#plan-a-large-batch) (Studio), and free space overall, before a batch.
- **Node 24.** Renders on Node 26 have hung while Chrome launched or closed; the CLI refuses it, and the local Studio runs on the Node that started it, so start it with Node 24.
